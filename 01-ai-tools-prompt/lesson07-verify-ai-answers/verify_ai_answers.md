## 1. 本课目标

学会验证 AI 的答案，而不是直接相信 AI 输出。

## 2. 重要程度

就业重要度：很高

原因：
AI 应用开发、RAG、Agent、SWE Agent 都需要验证模型输出。
Agent 如果盲目执行错误结果，可能会改错代码、调用错工具或产生错误答案。

## 3. AI 可能出错的地方

AI 可能会：
- 编造不存在的 API
- 使用过时的库用法
- 写出运行失败的代码
- 忽略边界条件
- 给出有安全风险的命令
- 用很自信的语气说错话

## 4. 四类答案的验证方法

| AI 答案类型 | 验证方法 |
|---|---|
| 事实类 | 查官方文档、权威来源、发布日期 |
| 代码类 | 运行代码、读报错、写测试 |
| 项目方案类 | 拆步骤、做最小版本 |
| 学习解释类 | 自己复述、做练习、换例子解释 |

## 5. 验证代码流程

1. 阅读 AI 生成的代码
2. 检查是否使用陌生库
3. 保存代码
4. 运行代码
5. 查看输出或报错
6. 把报错反馈给 AI
7. 修改后再次运行
8. 记录最终结果

## 6. 验证 Prompt 模板

```text
请不要直接认为你的答案一定正确。
请帮我检查上面的回答是否可能有问题。

请从以下角度检查：
1. 是否有事实错误
2. 是否有过时信息
3. 是否缺少前提条件
4. 是否有安全风险
5. 是否需要查官方文档确认
6. 如果是代码，是否需要运行测试

输出格式：
请用表格输出：
问题类型、可能风险、如何验证、优先级。
```

## 7. 我的理解

AI 的答案需要验证。
事实类答案要查来源，代码类答案要运行，项目方案要拆成小步骤验证。
真正的学习不是复制 AI 答案，而是能判断答案是否可靠。

## 8. 验证 AI 答案练习

### 练习 1：验证事实类答案

模糊问题：

```text
AI 告诉我某个库有一个函数，我应该怎么确认？
```

请写出你的验证步骤。

查找库来源，在其中查找是否有这个函数，并查询其作用和使用结果是否相同。

### 练习 2：验证代码类答案

假设 AI 给你写了一段 Python 代码。

请写出你会如何验证它是否正确，至少包含：
- 保存代码
- 运行命令
- 检查输出
- 处理报错
- 是否需要写测试

1、阅读AI给出的代码
2、查询是否有陌生库
3、保存代码
4、运行代码
5、查看输出和报错
6、将报错信息发给AI
7、再修改
8、记录最终结果

### 练习 3：验证项目方案

假设 AI 给你一个“个人知识库问答助手”的完整方案。

请写出你会如何判断这个方案是否适合初学者完成。

请不要直接认为你的答案一定正确。
请帮我检查上面的回答是否可能有问题。

请从以下角度检查：
1. 是否有事实错误
2. 是否有过时信息
3. 是否缺少前提条件
4. 是否有安全风险
5. 是否需要查官方文档确认
6. 如果是代码，是否需要运行测试
7. 过程是否通俗易懂
8. 是否含有高深技术词汇
9. 初学者能否完成

输出格式：
请用表格输出：
问题类型、可能风险、如何验证、优先级。


### 练习 1：验证事实类答案

如果 AI 告诉我某个库有一个函数，我会这样确认：

1. 先记录 AI 提到的库名、函数名和用途。
2. 打开这个库的官方文档，而不是只看博客或 AI 回答。
3. 在官方文档中搜索这个函数名。
4. 确认这个函数是否真的存在。
5. 查看函数的参数、返回值和示例代码。
6. 检查文档版本是否和我本地安装的库版本一致。
7. 如果本地已经安装这个库，可以在 Python 中尝试导入并调用。
8. 如果官方文档找不到这个函数，就不能直接相信 AI 的说法。

### 练习 2：验证代码类答案

如果 AI 给我写了一段 Python 代码，我会这样验证：

1. 先阅读代码，确认它是否符合我的原始需求。
2. 检查代码是否使用了我没学过或没安装的第三方库。
3. 如果有陌生库，先查官方文档，确认是否真的需要。
4. 把代码保存到对应的 `.py` 文件中。
5. 在终端运行代码，并记录运行命令。
6. 检查程序输出是否和期望结果一致。
7. 如果报错，复制完整 traceback，反馈给 AI。
8. 修改代码后再次运行。
9. 用一个简单输入测试基本功能。
10. 再用一个边界情况测试，例如空文件、错误路径、空关键词。
11. 如果这个功能比较重要，就写简单测试用例。
12. 记录最终可运行的版本和运行结果。


### 练习 3：验证项目方案

如果 AI 给我一个“个人知识库问答助手”的完整方案，我会从以下角度判断它是否适合初学者完成：

1. 是否明确说明项目目标，例如“基于我的文档回答问题”。
2. 是否拆成了多个小步骤，而不是一上来给完整复杂项目。
3. 是否先做最小可用版本。
4. 是否使用了我当前能理解的技术，例如 Python、文件读取、requests、JSON。
5. 是否引入太多陌生工具，例如复杂数据库、复杂前端、云部署、权限系统。
6. 是否说明每一步的输入、输出和完成标志。
7. 是否有明确的运行方式。
8. 如果涉及第三方库，是否能在官方文档中查到。
9. 如果涉及代码，是否可以逐步运行测试。
10. 是否考虑常见问题，例如文件为空、检索不到内容、API 请求失败。
11. 是否有安全风险，例如要求我暴露 API key。
12. 是否适合放进 GitHub 展示，例如有 README、示例数据和运行截图。

我的判断标准：
一个适合初学者的项目方案，应该先从最小可用版本开始，每一步都能运行、检查和复盘。
